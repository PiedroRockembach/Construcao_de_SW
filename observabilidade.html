Introdução à Observabilidade

Observabilidade é a capacidade de medir o estado interno de um sistema analisando os dados que ele gera, como logs, métricas e traces. Enquanto o monitoramento nos diz *se* algo está errado, a observabilidade nos ajuda a entender *por que* está errado. Em arquiteturas complexas e distribuídas, como microsserviços, é uma capacidade essencial para depurar e otimizar o desempenho.

Monitoramento vs. Observabilidade

Monitoramento: Baseado em dashboards pré-definidos para perguntas conhecidas ("Qual é o uso da CPU?").
Observabilidade: Permite fazer perguntas novas e exploratórias sobre o sistema para entender comportamentos inesperados ("Por que as requisições para o serviço de pagamento estão lentas apenas para usuários do Brasil?").

Os 3 Pilares da Observabilidade

A observabilidade é tradicionalmente construída sobre três pilares de dados telemétricos. Juntos, eles fornecem uma visão completa do comportamento do sistema, desde o nível macro (métricas) até o nível micro (logs e traces).

📜

Logs

Registros imutáveis e com timestamp de eventos discretos. São a forma mais detalhada de telemetria, ideais para entender o que aconteceu em um ponto específico no tempo.

📊

Métricas

Agregações numéricas de dados ao longo do tempo. Excelentes para identificar tendências, anomalias e para criar alertas (ex: uso de CPU, latência média).

🔗

Traces

Mostram a jornada completa de uma requisição através de múltiplos serviços. Essenciais para depurar gargalos de performance em sistemas distribuídos.

Pilar 1: Logs

Logs são a base da depuração. Para que sejam úteis em escala, eles devem ser estruturados (geralmente em formato JSON), permitindo buscas e agregações eficientes.

Frameworks e Ferramentas

  • SLF4J + Logback: A combinação padrão no ecossistema Spring. SLF4J é a fachada (API), e Logback é a implementação.
  • Logstash/Fluentd: Agentes para coletar, processar e encaminhar logs para um backend.
  • Elasticsearch/OpenSearch: Backends populares para armazenar e indexar logs.

Configuração (Logback para JSON)

Para gerar logs estruturados, configuramos um appender JSON no arquivo logback-spring.xml.

src/main/resources/logback-spring.xml
<!-- Exemplo de configuração Logback para output em JSON -->
<configuration>
    <appender name="jsonConsoleAppender" class="ch.qos.logback.core.ConsoleAppender">
        <encoder class="net.logstash.logback.encoder.LogstashEncoder" />
    </appender>

    <root level="INFO">
        <appender-ref ref="jsonConsoleAppender" />
    </root>
</configuration>

Exemplo de Código

Usando SLF4J em um serviço Spring para logar informações importantes.

UserService.java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;

@Service
public class UserService {
    private static final Logger logger = LoggerFactory.getLogger(UserService.class);

    public void createUser(String username) {
        logger.info("Criando usuário...", 
            net.logstash.logback.argument.StructuredArguments.kv("username", username));
        
        // ... lógica de criação ...
        
        logger.info("Usuário {} criado com sucesso.", username);
    }
}

Pilar 2: Métricas

Métricas são a primeira linha de defesa para entender a saúde do sistema. Elas são eficientes para armazenar e consultar, tornando-as ideais para dashboards e alertas.

Frameworks e Ferramentas

  • Micrometer: Fachada de métricas para a JVM, integrada ao Spring Boot Actuator. Permite instrumentar o código uma vez e exportar para vários sistemas.
  • Prometheus: Um banco de dados de séries temporais e sistema de monitoramento open-source. Ele funciona em um modelo de *pull*, onde raspa (scrape) métricas de endpoints HTTP.
  • Grafana: Uma plataforma de visualização para criar dashboards a partir de fontes de dados como o Prometheus.

Configuração (Spring + Prometheus)

Adicione as dependências do Actuator e do exportador Prometheus no pom.xml e configure o application.properties para expor o endpoint de métricas.

application.properties
# Expõe o endpoint do Prometheus via Actuator
management.endpoints.web.exposure.include=prometheus,health,info
management.endpoint.prometheus.enabled=true

Exemplo de Código (Métrica Customizada)

Criando um contador para registrar o número de usuários criados.

UserService.java com Micrometer
import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import org.springframework.stereotype.Service;

@Service
public class UserService {
    private final Counter usersCreatedCounter;

    public UserService(MeterRegistry meterRegistry) {
        this.usersCreatedCounter = Counter.builder("users.created.total")
            .description("Número total de usuários criados")
            .register(meterRegistry);
    }

    public void createUser(String username) {
        // ... lógica de criação ...
        usersCreatedCounter.increment();
    }
}

Pilar 3: Rastreamento Distribuído

Em microsserviços, uma única requisição pode passar por dezenas de serviços. O rastreamento distribuído conecta as operações de cada serviço em uma única visualização (o *trace*), permitindo identificar gargalos e entender o fluxo de ponta a ponta.

Frameworks e Ferramentas

  • OpenTelemetry: O padrão da indústria para instrumentação de telemetria. Fornece APIs e SDKs para gerar e exportar traces, métricas e logs. O Spring Boot 3+ tem integração nativa.
  • Jaeger & Zipkin: Backends open-source para coletar e visualizar traces.

Configuração (Spring + OpenTelemetry + Jaeger)

Com Spring Boot 3, a configuração é mínima. Adicione a dependência do OpenTelemetry e defina algumas propriedades para o exportador.

application.properties
# Nome do serviço que aparecerá no Jaeger
spring.application.name=user-service
# Habilita o exportador OTLP (OpenTelemetry Protocol)
management.otlp.tracing.endpoint=http://localhost:4318/v1/traces
# Probabilidade de amostragem (1.0 = 100% das requisições)
management.tracing.sampling.probability=1.0

Exemplo Completo: Endpoint de Criação de Usuário

Vamos unir todos os conceitos. Criaremos um endpoint POST /users que recebe dados, salva em um banco H2 e está totalmente instrumentado com logs estruturados, métricas customizadas e rastreamento distribuído.

1. Dependências (pom.xml)

Adicione as seguintes dependências ao seu projeto Spring Boot:

pom.xml
<dependencies>
    <!-- Web & Data -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>
    <dependency>
        <groupId>com.h2database</groupId>
        <artifactId>h2</artifactId>
        <scope>runtime</scope>
    </dependency>

    <!-- Observability -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-actuator</artifactId>
    </dependency>
    <dependency>
        <groupId>io.micrometer</groupId>
        <artifactId>micrometer-registry-prometheus</artifactId>
    </dependency>
    <dependency>
        <groupId>io.opentelemetry</groupId>
        <artifactId>opentelemetry-exporter-otlp</artifactId>
    </dependency>
    <dependency>
        <groupId>net.logstash.logback</groupId>
        <artifactId>logstash-logback-encoder</artifactId>
        <version>7.4</version>
    </dependency>
</dependencies>

2. Configuração (application.properties e logback-spring.xml)

Use as configurações já mostradas nas seções anteriores para habilitar os logs JSON, o endpoint do Prometheus e a exportação de traces para o Jaeger.

3. Código da Aplicação

Abaixo estão as classes principais para o nosso exemplo.

User.java (Entity)
// ... imports para JPA ...
@Entity
public class User {
    @Id @GeneratedValue private Long id;
    private String name;
    private String email;
    // Getters e Setters
}
UserRepository.java (Repository)
import org.springframework.data.jpa.repository.JpaRepository;
public interface UserRepository extends JpaRepository<User, Long> {}
UserService.java (Service com instrumentação)
// ... imports ...
@Service
public class UserService {
    private static final Logger logger = LoggerFactory.getLogger(UserService.class);
    private final UserRepository userRepository;
    private final Counter usersCreatedCounter;
    private final Tracer tracer;

    public UserService(UserRepository userRepository, MeterRegistry meterRegistry, Tracer tracer) {
        this.userRepository = userRepository;
        this.tracer = tracer;
        this.usersCreatedCounter = Counter.builder("api.users.created")
            .register(meterRegistry);
    }

    public User createUser(User user) {
        logger.info("Iniciando criação de usuário", kv("email", user.getEmail()));
        
        // Span customizado para a lógica de persistência
        Span persistenceSpan = this.tracer.nextSpan().name("saveUserToDatabase").start();
        try (Tracer.SpanInScope ws = this.tracer.withSpan(persistenceSpan)) {
             User savedUser = userRepository.save(user);
             persistenceSpan.event("Usuário salvo no BD");
             usersCreatedCounter.increment();
             logger.info("Usuário criado com sucesso", kv("userId", savedUser.getId()));
             return savedUser;
        } catch (Exception e) {
            persistenceSpan.error(e);
            throw e;
        } finally {
            persistenceSpan.end();
        }
    }
}
UserController.java (Controller)
// ... imports ...
@RestController
@RequestMapping("/users")
public class UserController {
    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping
    public ResponseEntity<User> createUser(@RequestBody User user) {
        User createdUser = userService.createUser(user);
        return ResponseEntity.status(HttpStatus.CREATED).body(createdUser);
    }
}

4. Executando e Observando

Para rodar o ambiente completo (Prometheus, Grafana, Jaeger), você pode usar um arquivo docker-compose.yml.

  1. Execute a aplicação Spring Boot.
  2. Execute docker-compose up -d.
  3. Envie uma requisição POST para http://localhost:8080/users com um JSON como {"name": "Ada Lovelace", "email": "ada@example.com"}.
  4. Logs: Verifique o console da sua aplicação para ver os logs em formato JSON.
  5. Métricas: Acesse o Prometheus em http://localhost:9090 e consulte pela métrica api_users_created_total.
  6. Traces: Acesse o Jaeger em http://localhost:16686, selecione o serviço user-service e encontre o trace da sua requisição.
